Stack Tecnológica

Tecnologias obrigatórias para ambas as implementações CQRS.
Vale tanto para Event Sourcing quanto para Replicação de Dados.

1. Stack Completa

TecnologiaVersãoPapel
Java 21 LTS Linguagem principal. Uso de Virtual Threads e Records obrigatórios.
Spring Boot 4.x Framework base das duas aplicações. Virtual Threads habilitadas via spring.threads.virtual.enabled=true.
Spring Web MVC via Spring Boot Camada HTTP. Usar MVC bloqueante — com Virtual Threads não há necessidade de WebFlux.
Spring Data JPA via Spring Boot Acesso ao banco de dados.
Flyway via Spring Boot Migrations de banco em ambas as aplicações.
PostgreSQL 16 Banco de dados. Uma instância para write, outra para read.
Maven 3.9+ Build tool e gerenciamento de dependências.
Docker Compose v2 Orquestração local de todos os serviços.
SonarQube Community Análise estática de complexidade ciclomática (McCabe) e Halstead.

2. Aplicações

Cada abordagem tem dois projetos Maven independentes.

AplicaçãoPortaResponsabilidade
Write App 8080 Recebe commands, executa aggregates, persiste no banco write.
Read App 8081 Serve queries, lê exclusivamente do banco read. Nunca escreve.

3. Banco de Dados

InstânciaDatabasePorta expostaQuem conecta
Write DB crm_write 5432 Write App
Read DB crm_read 5433 Read App
⚠
Read App nunca conecta no Write DB. A separação de datasources é uma fronteira arquitetural obrigatória em ambas as abordagens.

4. Docker Compose

docker-compose.ymlYAML
services:

  # ── Banco de escrita ─────────────────────────────────
  db-write:
    image: postgres:16
    container_name: crm-db-write
    environment:
      POSTGRES_DB: crm_write
      POSTGRES_USER: crm
      POSTGRES_PASSWORD: crm
    ports:
      - "5432:5432"
    networks:
      - crm-network

  # ── Banco de leitura ─────────────────────────────────
  db-read:
    image: postgres:16
    container_name: crm-db-read
    environment:
      POSTGRES_DB: crm_read
      POSTGRES_USER: crm
      POSTGRES_PASSWORD: crm
    ports:
      - "5433:5432"
    networks:
      - crm-network

  # ── Aplicação de escrita ──────────────────────────────
  write-app:
    build: ./write-app
    container_name: crm-write-app
    ports:
      - "8080:8080"
    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://db-write:5432/crm_write
      SPRING_DATASOURCE_USERNAME: crm
      SPRING_DATASOURCE_PASSWORD: crm
    depends_on:
      - db-write
    networks:
      - crm-network

  # ── Aplicação de leitura ──────────────────────────────
  read-app:
    build: ./read-app
    container_name: crm-read-app
    ports:
      - "8081:8080"
    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://db-read:5432/crm_read
      SPRING_DATASOURCE_USERNAME: crm
      SPRING_DATASOURCE_PASSWORD: crm
    depends_on:
      - db-read
    networks:
      - crm-network

networks:
  crm-network:
    driver: bridge

5. Rede e Comunicação entre Serviços

Todos os containers compartilham a rede crm-network. Dentro dela os serviços se comunicam pelo nome do container.

DeParaEndereço interno
Write App Write DB jdbc:postgresql://db-write:5432/crm_write
Read App Read DB jdbc:postgresql://db-read:5432/crm_read
Read DB (só na abordagem de Replicação) Write DB host=db-write — usado na configuração da subscrição WAL
ℹ
Por que rede bridge isolada? Garante que os containers se enxergam pelo nome do serviço (db-write, db-read) sem expor portas desnecessárias entre si. Apenas as portas declaradas em ports ficam acessíveis no host.
